## §3.3 — Red Team / Steelman (for the 3 highest-severity findings)

### Finding 1 — OS-language detection (verdict #1, HIGH)

- **RED TEAM:** Adding `navigator.language` detection introduces a subtle risk — a bilingual user who has their OS set to English (because their OS UI is in English) but prefers Arabic for worship content would be auto-defaulted to English on first launch. They would then have to override the auto-detection via Settings — which is the same trap, just inverted.
- **STEELMAN:** The detection runs **only on first launch** (gated on `!state.install.installed`); subsequent launches respect the user's explicit choice. A bilingual user who wants English-content-Arabic-chrome can switch once and it sticks. The default-English-status-quo traps **every** Arabic-only grandmother; the auto-detect-default-Arabic traps only the small subset of bilinguals who want English chrome + Arabic content. Asymmetric harm — fix wins.
- **VERDICT:** SHIP the fix; add a single onboarding step "Choose your language: العربية / English" so the user can override the detected default on first launch (covers the bilingual edge case).

### Finding 2 — Backup error i18n (verdict #2, HIGH)

- **RED TEAM:** Five new i18n pairs is small, but adds maintenance surface. If a future backup failure mode is added (e.g., "this file is encrypted"), the engineer must remember to add the i18n key in both AR and EN — otherwise the Part-4 orphan gate catches it but the feature ships late.
- **STEELMAN:** The Part-4 orphan gate is exactly the safety net that makes this safe — any future engineer who adds a backup error in EN-only will see the CI fail. The current state leaks English to a 70yo on her worst day (corrupt backup, lost hifz progress, English error she can't read). The asymmetry favors the fix 100:1.
- **VERDICT:** SHIP the fix; the maintenance burden is bounded by the orphan gate.

### Finding 3 — 8 failing tests + slim bundle data gap (verdict #3, HIGH)

- **RED TEAM:** Option (a) "bundle the 3 missing dirs" adds ~5 MB gz to the audit-slim zip — defeating "slim". Option (b) "SEED_SKIP env guard" risks hiding real regressions: if a future test legitimately needs tafsir data and the env guard silently skips it, the test passes vacuously.
- **STEELMAN:** Option (a) honors the existing tests + the brief's "unit 1843/1843" claim — if the slim bundle is supposed to be testable, it must ship the data the tests need. 5 MB gz is still slim. Option (b) is dangerous but only if env-guarded tests don't print a SKIP banner — `node --test` supports `t.skip()` which prints clearly. Recommend option (a) for the slim bundle + option (b) as a CI escape hatch (with `t.skip()` + reason).
- **VERDICT:** SHIP option (a) for the audit-slim zip; option (b) as a CI-only escape hatch with `t.skip('SEED_SKIP=1')` reason printed.
