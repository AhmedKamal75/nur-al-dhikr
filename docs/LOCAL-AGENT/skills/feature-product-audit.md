# Skill: Feature Product Audit

Review a feature using this sequence:

1. arrival
2. orientation
3. primary task
4. active interaction
5. secondary controls
6. progress/feedback
7. completion
8. recovery/error
9. empty state
10. exit/return path

At each stage ask:

- what is the user looking at?
- what can they do?
- what should they notice first?
- is there unnecessary UI?
- is state obvious?
- is the next action obvious?

A feature fails when it technically works but forces the user to parse the implementation instead of the task.
