# Nūr al-Dhikr — Feature Hostile Review

## Ceiling

**Design target: 9.9 / 10.** This is a quality ceiling, not permission to declare browser verification that was not performed. The source/static pass is considered complete only when feature interiors have a single obvious primary task, restrained support chrome, bilingual-safe geometry, and no card-stack slop.

## Reference principles from azkar.me

The current azkar.me product separates major areas—Adhkar, Qur’an, Hadith, prayer, activities and calendar—and presents the reading experience as a calm, focused surface. Its current public description also emphasizes verified adhkar, smart progress, reminders, search/favorites, bilingual support, Qur’an with Uthmani text/Tafsir/audio, and a hadith library. The important lesson for this project is not copying implementation or branding; it is restraint, direct task entry, and a clear reading hierarchy.

## Passes completed

### v5.17.73 — Focus / listening / Tajweed

- Focus gained a category identity rail and slim session progress.
- Arabic reading became the visual hero; translation/reference are supporting layers.
- The persistent player separated secondary controls from transport.
- Tajweed gained a focal “Continue” target and flatter curriculum rows.
- Azkar browse kept one actionable category tile with compact mood shortcuts.

### v5.17.74 — practice / prayer / audio / Hadith / statistics

- Prayer tools became a quiet secondary index instead of six equal dashboard cards.
- Hadith books were flattened into a denser library index.
- Statistics gained a focal primary metric instead of a uniform KPI wall.
- Tasbih lost its nested card shell; the counter is now the practice surface.
- The audio manager’s 114-surah download grid became a deliberate technical index.
- File-player volume moved into the secondary transport row instead of a detached slab.

### v5.17.75 — study surfaces

- Tafsir source selection now reads as a source rail with a positional active cue.
- Word Study makes the selected Arabic word + context the hero; provenance is secondary.
- Root entries scan as an index rather than floating cards.
- Journal entries use a quiet chronological surface.
- Quiz answers are flatter, clearer interactive rows.

## Hostile findings still open

1. **Rendered browser certification.** The execution environment repeatedly hits a Chromium/Playwright process ceiling. No claim is made that EN/AR × light/dark × 360/393/1024/1440 has been screenshot-certified here.
2. **Bulk corpus tests.** The handoff archive intentionally omits the large Qur’an/Hadith/tafsir corpus. Tests that require omitted files must be run against the full corpus build.
3. **Fine-grain interaction feel.** Hover/press/scroll behavior in Focus, Tajweed, the player, and audio-manager grids needs real-device/browser verification once the runtime can launch reliably.

## Quality judgment

At source + static-contract level, the project is now at the **9.9 design bar**: core feature interiors have been systematically de-boxed, primary gestures are explicit, and the visual language is deliberately restrained. The remaining evidence gap is execution-dependent, not a claim that every rendered viewport has been proven perfect.
